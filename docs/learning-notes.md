这份笔记记录已经完成并 review 过的练习：实际理解、错误、思考题和验证结果。通用接口及扩展用法按主题整理在 [知识专题](knowledge/README.md)，每日笔记链接到相应专题。扩展参考不代表已经掌握；未完成的算法题不提前写题解。

## 01 · 引用与 `const`

对应练习：[`cpp/01-references-const`](../cpp/01-references-const/)

- `T&` 是已有对象的别名。`swap_values(int& lhs, int& rhs)` 修改的是调用者传入的变量。
- `const T&` 可以避免复制对象，并禁止通过该引用修改对象。只读传入较大的 `std::vector` 时，适合写成 `const std::vector<int>&`。
- 值传递会创建一个独立的参数对象；引用传递访问原对象；指针传递也能访问原对象，但调用者和函数都需要处理指针的含义及可能的空值。
- `const int* p` 表示不能通过 `p` 修改所指向的整数；`int* const p` 表示 `p` 本身不能改指向。
- 返回引用不会产生独立的返回对象，因此必须保证被引用的对象仍然有效。不能返回局部变量的引用。
- `BufferView` 保存外部 `vector` 的引用，可以修改原数据，但不拥有它。外部 `vector` 必须比 `BufferView` 活得久；返回的元素引用也只在对应元素仍有效时可用。

### 相关专题

参见 [vector 的创建、访问、容量、增删与失效规则](knowledge/vector.md) 和 [引用绑定与生命周期](knowledge/move-semantics.md)。本练习的 `BufferView` 是借用容器的自定义视图，不是标准容器；它的 `at()` 通过 `vector::at()` 检查下标。

### 思考题

1. **为什么只读参数常用 `const std::vector<int>&`？** 传值会复制整份容器及其元素；`const` 引用不复制容器，也不允许函数经该引用修改它。函数若需要独立副本，传值才是有意的选择。
2. **`const int* p` 和 `int* const p` 有何区别？** 前者可以改 `p` 的指向，但不能经 `p` 改整数；后者不能改 `p` 的指向，但可以经 `p` 改整数。`const int* const p` 两项都禁止。
3. **为什么不能返回局部变量的引用？** 局部对象在函数返回时销毁；返回的引用随即悬空，之后读取或写入会产生未定义行为。返回值则把结果交给调用者。
4. **为什么 `BufferView` 不拥有 vector 的生命周期？** 它的成员是 `std::vector<int>&`，仅绑定已有容器，不创建或接管容器。调用者必须保证容器比视图活得久。

## 02 · 构造、析构与对象生命周期

对应练习：[`cpp/02-constructors-destructors`](../cpp/02-constructors-destructors/)

- 成员在构造函数体执行前就已经初始化。成员初始化列表用于直接初始化成员；在构造函数体中写赋值，则是在初始化完成后再次赋值。
- `const int id_` 必须在初始化列表中初始化，因为它不能先构造再赋值。引用成员也有类似要求。
- `explicit` 阻止构造函数被用于意外的隐式转换。
- `id() const` 末尾的 `const` 修饰成员函数，保证它不通过当前对象修改普通成员，并允许对 `const Connection` 调用。
- `name()` 返回 `const std::string&` 时避免复制字符串，但调用者不能通过它修改名称，且该引用的有效期受 `Connection` 对象及其成员状态约束。
- 局部对象离开作用域时自动调用析构函数。内层作用域的对象先析构，外层对象后析构。

### 本练习的接口约定

通用引用、返回值和资源语义见 [引用与移动语义](knowledge/move-semantics.md)。

| 接口或语法 | 本练习中的作用 | 使用时要注意 |
| --- | --- | --- |
| `Connection(int id, std::string name)` | 创建对象，并在初始化列表中建立 `id_`、`name_`、`connected_` | `explicit` 阻止适用情况下的隐式构造；成员实际按**声明顺序**初始化。 |
| `~Connection()` | 对象生命周期结束时自动调用 | 练习用日志观察析构；通常不应靠手动调用析构管理普通局部对象。 |
| `id() const`、`is_connected() const` | 分别返回 ID 和连接状态的值 | 返回的是副本；可在 `const Connection&` 上调用。 |
| `name() const` | 返回内部名称的 `const std::string&` | 避免复制，但不能在对象销毁后继续使用该引用。 |
| `connect()`、`disconnect()` | 把 `connected_` 设为 `true` / `false` | 非 `const` 成员函数；本练习允许重复调用。 |
| `inspect(const Connection&)` | 只读访问一个已有连接，不复制连接对象 | 函数不持有对象；调用期间对象必须有效。 |

### 思考题

1. **构造函数体执行前，成员存在吗？** 存在。进入函数体前，各成员已按声明顺序完成初始化。
2. **初始化列表与函数体赋值的区别？** 初始化列表直接建立成员初始状态；函数体赋值发生在成员已经初始化之后。对于 `std::string`，先默认构造再赋值通常多一步操作。
3. **为什么 `const int id_` 必须在初始化列表中设置？** `const` 成员建立后不能被赋值；要在它初始化时给出值，不能等到构造函数体。
4. **`is_connected() const` 的 `const` 修饰谁？** 修饰这个成员函数中的隐式对象参数，也就是限制通过当前 `Connection` 对象修改普通成员；它不是修饰返回的 `bool`。
5. **`name()` 返回 `const std::string&` 后调用者拿到什么？** 是内部 `name_` 的只读别名，不是新字符串。引用随 `Connection` 对象销毁而失效；若需独立保存，应复制为自己的 `std::string`。

## 03 · 拷贝语义与资源所有权

对应练习：[`cpp/03-copy-semantics`](../cpp/03-copy-semantics/)

| 写法 | 调用 | 对象状态 |
| --- | --- | --- |
| `Buffer b(a);` 或 `Buffer b = a;` | 拷贝构造函数 | 创建新对象 |
| 已有 `Buffer b(1);`，再执行 `b = a;` | 拷贝赋值运算符 | 修改已有对象 |

- `Buffer` 用 `new int[size_]{};` 分配数组并把元素初始化为 0；配对的释放方式是 `delete[] data_;`。`data_ = 0` 清空的是指针，不会初始化数组元素，还会丢失刚分配的内存。
- 拷贝构造要分配独立数组并复制所有元素。如果只复制 `data_` 指针，两个对象会共享同一块内存，修改互相影响，析构时还可能重复释放。
- 拷贝赋值的目标对象已经可能拥有数组。先按 `other.size_` 分配并复制新数组，再释放旧数组、接管新数组并更新 `size_`，可以避免丢失原资源，并在分配失败时保留旧状态。
- `this` 是指向当前对象的指针。执行 `b = a` 时，`this` 指向 `b`，`other` 引用 `a`；`this == &other` 用于识别 `b = b`。`return *this` 返回赋值后的对象引用，支持连续赋值。
- 复制循环要使用来源对象的大小。目标对象原来的 `size_` 可能不同；曾因按旧大小循环，导致新数组的一部分没有初始化。
- 当类直接拥有需要手动释放的资源时，要一起考虑析构、拷贝构造和拷贝赋值，这就是 Rule of Three。后续学习 RAII、智能指针和 Rule of Zero 时再比较如何简化所有权管理。

### 本练习的接口约定

通用引用、返回值和资源语义见 [引用与移动语义](knowledge/move-semantics.md)。

| 接口或语法 | 本练习中的作用 | 使用时要注意 |
| --- | --- | --- |
| `new int[size_]{}` | 分配 `size_` 个 `int` 并将其值初始化为 `0` | 成功后需要用 `delete[]` 释放；分配失败会抛异常。 |
| `delete[] data_` | 释放由 `new[]` 得到的整块数组 | 不可用单对象的 `delete` 代替；对 `nullptr` 使用 `delete[]` 是安全的。 |
| `Buffer(const Buffer&)` | 从已有对象创建新对象 | 必须分配独立数组并复制元素，避免共享裸指针。 |
| `Buffer& operator=(const Buffer&)` | 给已存在的对象赋值 | 先准备新资源，成功后再释放旧资源；返回 `*this`。 |
| `size() const` | 返回元素个数 | 返回 `std::size_t`，可用于 `for` 的边界。 |
| `at(i)` / `at(i) const` | 分别返回可写 / 只读的元素引用 | **本练习自定义的 `Buffer::at` 没有越界检查**，不同于 `std::vector::at`；调用者须保证 `i < size()`。 |

### 思考题

1. **`Buffer b = a;` 与已有 `b` 后执行 `b = a;` 为什么不同？** 前者创建新对象，调用拷贝构造；后者修改已有对象，调用拷贝赋值，必须处理 `b` 原本拥有的资源。
2. **如果直接复制 `data_` 指针会怎样？** 两个对象指向同一数组，不再是独立副本。修改一方会影响另一方。
3. **两个对象持有同一 `data_` 时析构会怎样？** 两者都会尝试 `delete[]` 同一地址，导致重复释放和未定义行为。
4. **拷贝赋值为什么要考虑目标的旧内存？** 目标在赋值前已经可能拥有数组；直接覆盖指针会泄漏旧数组。先建新数组还可在分配失败时保留原状态。
5. **为什么 `operator=` 返回 `T&`？** 返回当前对象的引用，符合普通赋值表达式的用法，并支持 `a = b = c`，无需额外复制对象。
6. **`this == &other` 防什么？** 防自赋值 `a = a` 时把数据来源当作旧资源释放或做无意义的重建。本实现检查后直接返回。

## 04 · RAII 与文件描述符所有权

对应练习：[`cpp/04-raii`](../cpp/04-raii/)

- `UniqueFd` 在构造时接管一个 fd，在析构时仅关闭有效 fd（`fd_ != -1`）。对象离开作用域时自动释放资源，调用者不再手动关闭它拥有的 fd。
- `get()` 只查看 fd，不转移所有权；`release()` 返回原 fd 并把成员设为 `-1`，调用者此后负责关闭它或交给其他对象。练习中的 `reset(transferred)` 将释放的同一个 fd 重新交给对象管理，并没有再次打开文件。
- `reset(new_fd)` 先判断是否与当前 fd 相同；相同则直接返回。否则关闭旧的有效 fd，再接管 `new_fd`。`reset()` 默认参数 `-1` 可用于清空对象。
- 禁止复制，避免两个对象认为自己拥有同一个 fd，导致重复关闭。移动语义留待后续阶段。
- Review 中发现过三处所有权错误：析构前先设为 `-1` 会漏关原 fd；`release()` 直接返回 `-1` 会丢失交出的 fd；`reset()` 若在比较相同 fd 前关闭旧 fd，会留下一个已关闭却仍被视为有效的 fd。逐一修正后，C++17 编译和练习自带程序运行通过。

### 本练习的接口约定

更多路径、目录遍历、文件流和 POSIX fd 用法见 [文件系统与文件 I/O](knowledge/filesystem-and-io.md)。`UniqueFd` 是本练习自定义类型，以下是它的具体约定。

| 接口或语法 | 本练习中的作用 | 使用时要注意 |
| --- | --- | --- |
| `::open("/dev/null", O_RDONLY)` | 打开文件，成功返回 fd，失败返回 `-1` | 原始 fd 是整数句柄；获得后要明确由谁负责关闭。 |
| `::close(fd)` | 关闭有效 fd；成功返回 `0`，失败返回 `-1` | `close()` 后不能继续使用旧 fd；不能把整数值相同误认为资源仍相同。 |
| `UniqueFd(raw)` | 接管 `raw` 的关闭责任 | 传入方此后不能再自行 `close(raw)`。 |
| `get() const` | 只读取当前 fd 数值 | **不交出所有权**；不要用所得数值另外创建一个也负责关闭的 `UniqueFd`。 |
| `valid() const` | 判断成员是否不等于 `-1` | 只反映包装器状态，不证明底层 fd 未被外部代码关闭。 |
| `release()` | 返回当前 fd，并把自身置为 `-1` | **不调用 `close`**；接收方必须安排后续关闭。 |
| `reset(new_fd)` / `reset()` | 关闭旧的不同 fd 并接管新 fd / 关闭后清空 | 相同 fd 时不先关闭；默认参数为 `-1`。 |
| `= delete` | 禁止拷贝构造和拷贝赋值 | 防止两个包装器拥有同一 fd。 |

### 思考题

1. **为什么析构函数不应该随意抛异常？** 析构可能发生在异常传播过程中；如果此时再抛出异常，程序会调用 `std::terminate()`。因此析构应完成清理且不让异常逸出。
2. **为什么 fd 包装类不应该默认可复制？** 复制整数 fd 不会复制底层资源的独立所有权。两个包装对象若都关闭同一个 fd，就可能重复关闭，甚至误关后来复用该编号的其他资源。独占所有权的包装类应禁止复制。
3. **`release()` 和 `reset()` 的所有权语义有什么区别？** `release()` 只交出当前 fd，不关闭它；`reset()` 关闭当前拥有的不同 fd，并接管传入的 fd。调用 `reset()` 后，传入方不应再自行关闭该 fd。
4. **`close()` 返回错误时，析构函数应该怎样处理？** 析构不能把错误作为异常抛给调用者；可以按需要记录或统计错误，但不能依赖调用者处理返回值。对这份练习，析构调用 `close()` 后忽略其返回值即可；若业务必须获知关闭错误，应提供显式操作在析构前处理。不要在析构中盲目重试 `close()`，因为 fd 编号可能已被系统复用。

## 05 · 智能指针与动态对象所有权

对应练习：[`cpp/05-smart-pointers`](../cpp/05-smart-pointers/)

- `make_session` 用 `std::make_unique<Session>` 创建对象并返回 `unique_ptr`。直接返回临时对象不需要额外 `std::move`；先存入局部 `unique_ptr` 再返回，也能按移动语义返回。
- `SessionManager::add` 通过 `std::move(session)` 把独占所有权放入 `vector`。移动后不能再把原指针当作对象使用；`count() const` 用 `size()` 查询容器元素数。
- 遍历 `vector<unique_ptr<Session>>` 时，用 `const auto&` 引用元素，避免复制不可复制的 `unique_ptr`；通过公开的 `name()` 读取私有成员。练习中曾尝试用 `int` 接收元素并直接访问 `name_`，类型和访问权限均不正确。
- `SharedSessionRegistry::publish` 保存一个 `shared_ptr`，与调用者共享所有权；`observe` 从它创建 `weak_ptr`，观察者不增加共享所有者数量。使用前通过 `lock()` 检查对象是否仍存活。
- `clear()` 调用 `current_.reset()` 放弃 Registry 的所有权，不能手动 `delete` 所管理的对象。运行中，`monitor` 在调用者 `shared.reset()` 与 Registry `clear()` 都完成后析构；`radius-client` 在 `manager` 生命周期结束时析构。
- 使用 C++17、`-Wall -Wextra -Wpedantic -Werror` 编译通过，练习程序输出与上述生命周期一致。

### 相关专题与本练习接口

[智能指针专题](knowledge/smart-pointers.md) 整理了创建、get/release/reset、数组、自定义删除器、共享控制块、weak_ptr 和参数设计；[vector 专题](knowledge/vector.md) 补充了不可复制元素的存储与失效规则。

本练习 `publish(std::shared_ptr<Session> session)` 的按值参数允许函数保留共享所有权，`current_ = session` 让 Registry 成为所有者；`observe()` 返回 weak_ptr 提供观察能力。只在调用期间读取 Session 时，通常用 `const Session&`，无需引入共享所有权。

### 思考题

1. **为什么 `unique_ptr` 不可复制但可以移动？** 复制会让两个指针都声称独占同一对象，导致所有权冲突；移动把所有权交给新指针，原指针变空，始终只有一个所有者。
2. **`shared_ptr` 的引用计数与对象自身的引用有何区别？** 共享引用计数记录有多少个 `shared_ptr` 共同拥有该对象，通常保存在独立的控制块中，不是 `Session` 类的引用成员，也不是 `Session&`。普通引用或裸指针不会增加该计数。
3. **为什么 `weak_ptr` 不延长生命周期？** 它只关联共享控制块，不计入强所有者数量。强所有者数量归零时，对象会析构；此后 `lock()` 返回空指针。控制块可能因仍有 `weak_ptr` 而继续存在，但对象本身已销毁。
4. **何时用 `const Session&` 而非 `shared_ptr<Session>` 参数？** 函数只在调用期间读取对象、不保存它且不需要共享所有权时，用 `const Session&`。函数要在调用结束后继续持有对象，或明确成为共享所有者时，才接收 `shared_ptr`。如果允许“没有对象”，还需选用能表达空值的接口。
5. **何时避免 `shared_ptr`？** 所有者清晰且只有一个时用 `unique_ptr` 更直接；只借用对象时用引用或裸指针表达非拥有关系。滥用共享所有权会模糊销毁时机，互相持有的 `shared_ptr` 还可能形成循环引用，应在观察关系上使用 `weak_ptr`。

## 06 · 值类别与移动语义

对应练习：[`cpp/06-move-semantics`](../cpp/06-move-semantics/)，2026-10-12 完成并 review。

### 从本次代码理解移动

- `MovableBuffer` 独占一个动态整数数组，负责在析构时调用 `delete[]`。复制操作被删除；移动操作把数组所有权交给目标对象，原数组地址和元素不变，不需要重新分配数组或逐个复制元素。
- `MovableBuffer&& other` 中，`&&` 表示右值引用，`other` 是参数名，不是指针。执行 `MovableBuffer second(std::move(first))` 时，`other` 引用的就是 `first`；修改 `other.data_` 和 `other.size_` 会修改 `first` 的成员。绑定引用本身不创建另一个 Buffer，也不转移资源。
- 移动构造用于创建新对象：接管来源的指针和大小，然后把来源设为 `nullptr`、`0`。移动赋值用于修改已有对象：先判断自移动，再释放目标原有数组，接管来源资源并清空来源，最后返回 `*this`。
- 名称是“移动赋值”，不是“移动复制”。本题中不同对象间的移动会让来源处于明确的空状态，而不是恢复到创建时的状态。这个类没有默认构造函数。其他类型的移动后状态取决于类型约定；标准库类型通常保证有效但状态未指定，除非有更具体的保证，不能一概认为都会变空。
- 来源对象移动后仍然存在，会正常析构，也可以重新接受移动赋值。它的大小为 `0` 时没有有效元素下标，不能调用 `get(0)` 或 `set(0, value)`。本实现对自移动直接返回，因此 `third = std::move(third)` 保持原资源和数据。

### 左值、右值与引用参数

值类别描述的是表达式。表达式 `first` 是左值，表示一个有身份的对象；`std::move(first)` 是亡值，属于右值，仍指向同一个对象。纯右值（例如 `42`）也是右值的一类。

```cpp
int value = 10;
int& alias = value;             // 左值引用，引用 value
int&& temporary = 20;           // 绑定临时对象，临时对象寿命延长到该局部引用的寿命
int&& movable = std::move(value); // 仍然引用 value，没有新建或搬走一个 int
```

普通左值不能直接绑定到本题的 `MovableBuffer&&` 参数。禁用复制后，`MovableBuffer second(first)` 无法编译；`MovableBuffer second(std::move(first))` 可以选择移动构造。但仅把 `first` 传给接收 `MovableBuffer&` 或 `const MovableBuffer&` 的函数，不涉及复制，可以直接传递。

`other` 的声明类型虽然是右值引用，但函数体中表达式 `other` 是左值。引用类型与使用名字时的表达式值类别要分开理解。如果要把 `other` 继续交给另一个要求右值的接口，需要再次使用 `std::move(other)`；本题直接访问其成员即可。

### 相关专题与本练习接口

[引用与移动语义专题](knowledge/move-semantics.md) 覆盖引用绑定、std::move、const 对移动的影响、移动构造与赋值、noexcept、返回值和数组资源。与容器和智能指针配合的用法见 [vector](knowledge/vector.md) 与 [智能指针](knowledge/smart-pointers.md)。

本练习 `size()` 返回元素个数；`data()` 的 const / 非 const 重载分别返回 `const int*` / `int*`，只借用地址，不转移所有权；`set(index, value)` 返回 void，`get(index) const` 返回整数副本，两者都要求有效下标，没有越界检查。移动后原数组的借用指针由新所有者的资源寿命约束。

### 本次错误与修正

初版移动赋值重新 `new[]` 并循环复制元素，随后直接覆盖 `data_`，存在三个问题：目标旧数组未释放而泄漏；来源仍保留数组，执行的是深拷贝而非题目要求的所有权转移；分配失败时异常会逃出 `noexcept` 函数并终止程序。当时输出 `second size after assignment: 3`，暴露了来源未清空的问题。

最终实现保留自移动检查，释放目标旧数组，接管来源地址和大小，再清空来源。移动构造和移动赋值均只需 O(1) 时间与 O(1) 额外空间（本题元素类型为 `int`），无需复制所有元素。自移动时直接返回，防止先释放自己的资源再从自身读取。

### 思考题

1. **`std::move` 到底执行了什么？为什么它本身不搬运内存？** 它执行类型转换，使结果表达式可参与移动操作的重载选择，仍引用原对象。它不知道某个类如何管理资源；数组指针的接管、旧内存的释放和来源清空，都由本题的移动构造或移动赋值实现。单独调用 `std::move(first)` 不会改变 `first` 的成员。
2. **`Buffer&& other` 虽然是右值引用，表达式 `other` 在函数体里属于左值还是右值？** 属于左值。`&&` 是声明的引用类型，名字 `other` 在表达式中表示一个可持续访问的对象；需要将它继续作为可移动来源传递时，可用 `std::move(other)` 得到亡值表达式。
3. **为什么移动构造和移动赋值通常标注 `noexcept`？** 资源接管通常只改指针等成员，可以承诺不抛异常，也便于调用方推理异常安全。以 `std::vector` 扩容为例，它需要构造新位置的元素；不抛异常的移动构造让它能安全选择移动。若移动可能抛异常且复制可用，它可能选择复制来保留异常保证。不要为了形式标注 `noexcept` 却在内部执行可能失败的分配且不处理异常。
4. **为什么 move 后的对象必须仍然可安全析构？** 移动操作没有结束来源对象的生命周期；局部对象离开作用域时仍会析构。本题把来源指针设为空，让析构中的 `delete[]` 不再释放已转出的数组，同时把大小设为 0，保持成员状态一致。
5. **`Buffer a = std::move(b)` 和 `a = std::move(b)` 分别调用什么？** 前者在声明中初始化新对象，调用移动构造，即使写了 `=` 也不是赋值；后者给已经存在的对象赋值，调用移动赋值，必须处理 `a` 原先拥有的资源。本题自移动赋值则保持对象原状。

## 07 · Rule of Zero / Five

对应练习：[`cpp/07-rule-of-zero-five`](../cpp/07-rule-of-zero-five/)，2026-10-13 完成并 review。

### 代码与所有权

- `LegacyBuffer` 独占 `new int[size_]{}` 分配的数组，并在析构时 `delete[]`。拷贝构造分配新数组并逐个复制，拷贝赋值先分配、复制，再释放旧数组和更新成员；因此两个副本互不影响，分配失败时目标保持原状。
- 移动构造和移动赋值只接管指针与大小，并将来源置为 `nullptr`、`0`。移动赋值先处理目标旧数组，且先检查自移动；两种移动操作均无需分配，适合标为 `noexcept`。本类明确约定移动后来源为空。
- `ModernBuffer` 只保存 `std::vector<int>`，通过成员初始化列表 `data_(size)` 创建 `size` 个零值元素。它不声明析构、拷贝或移动特殊成员函数；vector 负责资源释放、独立复制和移动。`size()` 返回 `data_.size()`。
- 两种 `at()` 都返回内部元素的引用，并假定 `index < size()`，不会检查下标。引用在所属对象销毁后失效；ModernBuffer 的 vector 若重新分配，旧元素引用也会失效。这些自定义 `at()` 与会抛出 `std::out_of_range` 的 `std::vector::at()` 不同。
- 对比：LegacyBuffer 需要维护五个特殊成员函数及指针和大小的不变式；ModernBuffer 把资源管理交给 vector，代码更少，复制失败时的清理也由容器完成。两者复制 `n` 个 `int` 均为 O(n)；LegacyBuffer 的移动为 O(1)，此处使用默认分配器的 vector 移动构造通常也是 O(1)，不能把该复杂度推广到所有移动情形。

### 本次错误与修正

初版 `LegacyBuffer::at()` 在越界时尝试 `return -1`：非 const 的 `int&` 不能绑定这个临时值，const 的 `const int&` 即使绑定成功也会在返回后悬空；`std::size_t index < 0` 恒为假。按练习的有效下标前提，最后直接返回数组元素。`ModernBuffer::size()` 曾保留模板中的 `return 0`，后改为 `data_.size()`。构造 vector 时选用 `data_(size)`；`data_{size}` 对 `vector<int>` 会创建一个值为 `size` 的元素，语义不同。

相关接口、特殊成员函数生成规则与异常安全见 [Rule of Zero / Five 专题](knowledge/rule-of-zero-five.md)；vector 的构造、访问、容量和失效规则见 [vector 专题](knowledge/vector.md)，移动表达式与资源转移见 [引用与移动语义](knowledge/move-semantics.md)。专题中的扩展用法不表示已在本练习中验证。

### 思考题

1. **为什么写了析构函数以后，隐式移动行为会受到影响？** 用户声明析构函数后，编译器不会再隐式声明移动构造和移动赋值。即便把对象写成 `std::move(x)`，它仍可能匹配拷贝函数；需要的移动操作要显式设计。本练习的 LegacyBuffer 因管理裸指针而手写移动，ModernBuffer 没有声明析构函数，所以能使用成员支持的隐式移动。
2. **Rule of Five 是要求所有类都手写五个函数吗？** 不是。它提醒手动管理资源并自定义一个特殊成员函数时，应一起审视其余几个操作；不合理的复制可以 `= delete`。如果成员已负责资源管理，优先考虑 Rule of Zero，无需为形式凑齐五个函数。
3. **为什么 ModernBuffer 不需要手写析构函数？** vector 成员在 ModernBuffer 析构时自动析构，并释放它拥有的存储及元素；没有裸资源需要类本身清理。
4. **std::vector 的复制和移动分别是什么语义？** 复制产生独立的元素序列，修改其中一份的 `int` 不影响另一份；移动把来源资源或元素状态转给目标，来源仍有效但状态通常未指定，不能一律假定其大小为 0。本练习验证了移动目标的数据，没有依赖移动来源的大小。
5. **如果类拥有一个独占的 Linux fd，它一定应该支持复制吗？** 不一定。直接复制 fd 整数会让两个对象都认为自己负责关闭同一资源；独占 fd 包装类通常删除复制操作并支持移动。如果确实需要独立句柄，应明确通过 `dup` 等系统调用定义复制语义并处理失败，而不是默认复制整数。
